# Background jobs

Everything that runs without a user clicking. Production runs them from the
**server's crontab** (installed by `scripts/install-server-cron.sh`), each line
calling `scripts/run-cron.sh /api/cron/<job>`, which curls
`https://app.lovelab-antwerp.com<path>` with the `x-vercel-cron-secret`
header read from the app's `.env`. `vercel.json` lists the same schedules but
Vercel no longer runs anything. Routes: [04-endpoints/cron-and-backup.md](04-endpoints/cron-and-backup.md).

| When (server clock) | Job | What happens | Writes |
|---|---|---|---|
| 04:00 daily | `health-check` | `lib/healthCheck.runDailyHealthCheck`: ghost commissions (pending rows whose document is trashed), duplicate agent folders, schema drift against `lib/expected-schema.mjs` | `system_health_events`; email to admins for error / critical (`lib/healthEvent.js`, max one per source+severity per 30 min) |
| 06:00 daily | `email-deliveries` | `sweepPendingDeliveries(200)`: ask Resend about deliveries still `sent` / `delivery_delayed` / `unknown` after 10 min | `email_deliveries`, mirrored to `documents.metadata.email` and `fair_email_drafts`; alerts on bounces |
| 01:00 daily | `igi-stock` | `syncShelfSnapshot`: ERP `certificate-stock` (BELGIUM) → match LGAJ serials → upsert | `igi_shelf_snapshots`; nothing on failure |
| every 10 min | `igi-certificate-outs` | `syncCertificateIns`, `syncCertificateOuts` (full reconcile incl. deletes), `syncShelfSnapshot`, `syncAllModelsToCertificateMaster`, `retryFailedReceipts` | `igi_certificate_in_sync`, `igi_certificate_out_sync`, `igi_shelf_snapshots`, `igi_receipts`; ERP `certificate-master` |
| hourly | `igi-mail` | reads the clock in Europe/Brussels: 07:00 morning digest to Liuba; Friday 14:00 weekly digest to IGI; Friday 14:00 in even ISO weeks order digest to Alberto. `?force=morning\|weekly\|order` sends one now | `igi_digest_sends` (one per kind per day); emails |
| 1st of month 08:00 (n8n) | `POST /api/commission-reports/generate` | **disabled** in the route (`{ disabled: true }`); reports are generated by hand from the agent page | |
| never | `GET /api/backup` | ~30 tables as JSON + storage prefixes into a dated Drive folder; `{ skipped: true }` without Drive credentials | Google Drive; email on failure |

## Things that happen in the request but asynchronously

Not cron, but worth knowing because they can fail after the HTTP response:

| Trigger | Work | Failure handling |
|---|---|---|
| order saved / updated / emailed | internal notice email to `ORDER_NOTIFICATION_EMAILS` (+ extras) | logged, health event |
| consignment / delete_from_stock order saved | ERP push (`lib/lovelab-sync.js`) | health event; manual `undo-return` exists |
| IGI visit received | ERP `certificate-in` push | `igi_receipts` row `failed`, retried by the 10-min cron |
| agent invited | Google Drive folder creation | logged; `POST /api/agents/[id]/repair` recreates |
| organization created / member added | storage folder markers | logged "non-blocking" |
| email bounced / complained | admin alert email | throttled by `lib/healthEvent.js` |

## Operating the jobs

```bash
# on the server
crontab -l                                              # see the five lines
/var/www/app.lovelab-antwerp.com/scripts/run-cron.sh /api/cron/igi-mail?force=morning
pm2 logs app-lovelab-antwerp --lines 200 | grep cron
```

Health events show up under Admin → System health
(`system_health_events`, admin-only RLS). Resolve them there
(`resolved_at`, `resolved_note`).

Known gaps: no job reconciles pending commissions of soft-deleted agents (gap 3
in `docs/cascade-delete-audit.md`); the backup is not scheduled; there is no
alert when a cron stops running (consider a dead-man's switch on the hourly
`igi-mail` call).
